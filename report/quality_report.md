# Отчёт о качестве данных

**Датасет:** `Pokemon.csv`  
**Размер:** 800 строк × 13 столбцов  
**Источник:** датасет о покемонах 1–6 поколений (включая мега-эволюции и альтернативные формы)

---

## 1. Введение

Датасет содержит информацию о 800 покемонах из шести поколений: их боевые
характеристики (HP, Attack, Defense, Sp. Atk, Sp. Def, Speed, суммарный Total),
типы (Type 1 и Type 2), номер поколения и флаг легендарности. Данные носят
смешанный характер — числовые, категориальные и булевы признаки — и включают
базовые формы, эволюции, мега-эволюции и региональные варианты.

**Заказчик** — разработчики игр серии Pokémon, аналитики киберспортивного
сообщества (VGC, Pokémon Showdown) и исследователи игрового баланса.

**Возможные задачи ИАД:**
1. Описательная аналитика и профилирование покемонов по типам и поколениям.
2. Поиск аномалий (несбалансированные характеристики).
3. Классификация `Legendary` по боевым характеристикам.
4. Кластеризация покемонов по архетипам (танк / аттакер / спидстер).
5. Прогнозирование `Type 1` по характеристикам.

---

## 2. Паспорт датасета

| Признак | Тип | Описание |
|---|---|---|
| `ID` (бывш. `#`) | int | Национальный номер покемона (не уникален) |
| `Name` | str | Имя покемона с формой |
| `Type_1` | str | Основной тип |
| `Type_2` | str | Второй тип (может отсутствовать) |
| `HP` | int | Очки здоровья |
| `Attack` | int | Физическая атака |
| `Defense` | int | Физическая защита |
| `Sp_Atk` | int | Специальная атака |
| `Sp_Def` | int | Специальная защита |
| `Speed` | int | Скорость |
| `Total` | int | Сумма характеристик |
| `Generation` | int | Поколение (1–6) |
| `Legendary` | bool | Легендарность |

Производные признаки, добавленные в ходе анализа:
- `Has_Type_2` — флаг наличия второго типа.
- `Is_Mega` — флаг принадлежности к мега-эволюции.

## 3. Основные проблемы качества данных

| № | Тип проблемы | Описание (где и что) | Потенциальный риск | Предлагаемое решение |
|---|---|---|---|---|
| 1 | Пропуски | `Type 2` пуст в ~48% строк | Нельзя использовать как обычный категориальный признак | Заменить на `"None"` или добавить флаг `Has_Type_2` |
| 2 | Дубликаты | `ID` повторяется у мега-форм и альтернативных вариантов | Неверная агрегация по `ID` | Использовать `Name` как уникальный ключ |
| 3 | Проблемные имена столбцов | `Type 1`, `Type 2`, `Sp. Atk`, `Sp. Def`, `#` | Неудобно писать код, конфликты с Pandas-атрибутами | Переименовать: `Type_1`, `Type_2`, `Sp_Atk`, `Sp_Def`, `ID` (сделано) |
| 4 | Согласованность Total | `Total` не всегда равен сумме характеристик (если обнаружено) | Ошибки при агрегациях по Total | Пересчитать или исключить несоответствия |
| 5 | Спецсимволы в именах | `Nidoran♀`, `Nidoran♂`, `Farfetch'd`, `Flabébé`, `Mr. Mime` | Проблемы при экспорте в другие форматы (CSV/JSON/SQL) | Оставить как есть, либо нормализовать Unicode |
| 6 | Склеенные имена форм | `VenusaurMega Venusaur`, `CharizardMega Charizard X` | Сложно выделить базовую форму | Извлечь префикс до `"Mega"` в отдельный признак `Base_Name` |
| 7 | Выбросы по Total | Отдельные покемоны имеют `Total > 600` (Mewtwo Mega, Rayquaza Mega) | Искажение среднего | Это осмысленные биологические выбросы — не удалять |

---

## 4. План улучшения качества

### Приоритет 1 — критично
1. Переименовать столбцы (`Type 1 → Type_1`, `Sp. Atk → Sp_Atk`, `# → ID`).
2. Обработать `Type 2`: добавить `Has_Type_2` (сделано).
3. Проверить согласованность `Total` со суммой характеристик.

### Приоритет 2 — важно
4. Выделить признак `Is_Mega` из имени (сделано).
5. Выделить базовое имя покемона (без суффикса мега-эволюции) — для агрегаций по видам.
6. Проверить корректность Generation у альтернативных форм.

### Приоритет 3 — можно отложить
7. One-Hot / Ordinal encoding категориальных признаков.
8. Нормализация числовых характеристик (StandardScaler / MinMaxScaler).
9. Построение baseline-модели для классификации `Legendary` или `Type_1`.
10. Кластеризация покемонов по боевому профилю.

---

## 5. Краткое резюме

В ходе работы был проведён первичный обзор и аудит качества датасета
`Pokemon.csv`. Данные объёмны (800 записей), имеют смешанные типы признаков
и содержат осмысленные пропуски (`Type 2`), которые объясняются природой
данных, а не ошибками ввода. Основные проблемы — неудобные имена столбцов
и повторяющийся `ID` у альтернативных форм.

Датасет полностью пригоден для ИАД после небольшой нормализации имён столбцов
и обработки пропусков в `Type 2`. Отдельного внимания заслуживают
потенциальные задачи классификации легендарности, кластеризации по
архетипам и анализа игрового баланса между поколениями.

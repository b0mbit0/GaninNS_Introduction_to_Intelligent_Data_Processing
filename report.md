# Отчёт по лабораторной работе №1

## Датасет

Pokemon.csv, ~800 строк, 13 столбцов. Информация о покемонах: имя, типы, шесть базовых статов, суммарный Total, номер поколения и признак Legendary.

Заказчик — условно игровая студия или аналитики киберспорта.

Задачи, которые можно решать:
- кластеризация покемонов по характеристикам;
- предсказание Legendary;
- поиск выбросов;
- сравнение поколений и типов.

Поколение (Generation) считаем временным признаком: они выходили по порядку (1996, 1999, 2002, 2006, 2010, 2013). Дополнительно добавили datetime-столбец release_year.

## Паспорт

Размер: ~800 строк, 13 столбцов + 1 производный (release_year).

Основные признаки:
- # — номер в покедексе
- Name — имя (иногда с формой)
- Type 1, Type 2 — боевые типы
- Total — сумма статов
- HP, Attack, Defense, Sp. Atk, Sp. Def, Speed — базовые статы
- Generation — поколение 1-6
- Legendary — легендарный или нет

## Проблемы качества

| № | Проблема | Где | Риск | Что делать |
|---|---|---|---|---|
| 1 | Пропуски | Type 2, ~48% строк | Нельзя подать в модели как есть | Заменить на "None" как отдельную категорию |
| 2 | Дубликаты по # | Мега-эволюции и формы | # нельзя использовать как уникальный ключ | Оставить как есть |
| 3 | Выбросы | HP, Defense, Speed и др. | Мешают линейным моделям | Не удалять, использовать устойчивые модели или флаг |
| 4 | Дисбаланс | Legendary True ~8% | Плохое качество классификации | Stratified split + class_weight |
| 5 | Слипшиеся имена | Name: "VenusaurMega Venusaur" и подобные | Неудобно группировать по имени | При необходимости вытащить форму регуляркой |
| 6 | Мультиколлинеарность | Total = сумма статов | Линейные модели получают лишнее | Использовать либо Total, либо отдельные статы |
| 7 | Тип Generation | Изначально int | Может трактоваться как непрерывный | Привести к category |

## План улучшения

1. Обязательно:
   - Type 2 заполнить "None";
   - Generation и Legendary привести к category;
   - добавить release_year как datetime.

2. Важно:
   - учесть дисбаланс Legendary при обучении;
   - нормализовать статы для кластеризации.

3. По возможности:
   - вытащить form из Name;
   - добавить is_outlier вместо удаления выбросов.

4. Отложить:
   - one-hot для типов;
   - агрегацию мега-форм с базовыми.

## Резюме

Данные в целом качественные. Основная возня — с Type 2 (структурные пропуски) и с Legendary (дисбаланс классов). Выбросы по статам — не ошибки, а игровая механика, удалять их не нужно. Для дальнейшего анализа стоит держать в голове мультиколлинеарность Total и корректно кодировать категориальные признаки.
